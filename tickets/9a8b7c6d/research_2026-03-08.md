# Research: Core Auth Implementation

**Date**: 2026-03-08

## 1. Executive Summary
The project currently has no authentication logic. Both the mobile (Expo) and API (NestJS) applications are in their default scaffolded states.

## 2. Technical Context
- **Affected components**: `apps/mobile`, `apps/api`.
- **Current behavior**: No authentication or user management exists.
- **Logic and data flow**: N/A.

## 3. Findings & Analysis
- **Mobile State**: `App.js` is the default Expo entry point. No navigation or auth screens exist.
- **API State**: Default NestJS controller and module. No middleware or guards for authentication.
- **Auth Options**:
  - Supabase Auth: Well-integrated with Postgres (which we just added).
  - Clerk: High-level managed auth.
  - Decision: Per `TECH_STACK.md`, we should prioritize tools that work well with our offline-first and Postgres setup. Supabase is a strong candidate given the PowerSync integration.

## 4. Technical Constraints
- Requires selection of an Auth provider and registration of the application.
- Mobile auth requires handling deep links for redirecting after login.
- API requires a way to verify JWTs from the selected provider.

## 5. Architecture Documentation
The architecture requires a centralized auth provider that issues JWTs. These tokens will be used by the mobile app to authenticate requests to the API and potentially for PowerSync's own authentication/authorization layer.
