# Research: Setup PowerSync Mobile Client

**Date**: 2026-03-08

## 1. Executive Summary
The goal is to integrate the PowerSync SDK into the Expo mobile application to enable offline-first data synchronization. This requires installing the necessary dependencies, initializing the PowerSync client, and defining a local schema that mirrors the Postgres backend.

## 2. Technical Context
- **Affected components**: `apps/mobile`, specifically `src/lib/` and `App.js`.
- **Current behavior**: The mobile app has Supabase Auth integrated but no local database or sync logic.
- **Logic and data flow**: Supabase handles authentication. PowerSync will use the Supabase JWT to authenticate with the sync service and replicate data to a local SQLite database.

## 3. Findings & Analysis
- **Dependencies**:
  - `@powersync/react-native`: The core SDK.
  - `expo-sqlite`: The SQLite driver for Expo.
  - `react-native-get-random-values`: Required for UUID generation in some environments.
- **PowerSync Initialization**: Requires a `PowerSyncDatabase` instance, a `Schema`, and a `Connector` (to handle auth and sync service connection).
- **Local Schema**: Must define the tables that PowerSync will manage locally (e.g., `inventory_items`, `households`).
- **Connector Implementation**: Needs to fetch the current Supabase session token and provide it to PowerSync.

## 4. Technical Constraints
- PowerSync requires a specific `Schema` object defined in TypeScript.
- The sync service is currently configured to run on port 8080 (from `powersync.yaml`).
- Authentication must be handled by providing the Supabase JWT to the PowerSync connector.

## 5. Architecture Documentation
The mobile app will interact with a local SQLite database through the PowerSync SDK. The SDK handles all the heavy lifting of background synchronization, conflict resolution (per our LWW strategy), and offline access.
