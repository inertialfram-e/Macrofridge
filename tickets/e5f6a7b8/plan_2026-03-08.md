# PowerSync Backend Sync Rules Implementation Plan

## Overview
Define and implement the authorization and data filtering logic in the PowerSync sync service. This ensures that users only receive data relevant to their specific households, maintaining privacy and optimizing sync performance.

## Scope Definition (CRITICAL)
### In Scope
- Update `powersync.yaml` with the final sync rules.
- Implement filtering logic for `users`, `households`, `household_members`, `inventory_items`, and `transactions`.
- Configure `products` as a global sync table.
- Ensure the use of `request.auth.sub` for identity-based filtering.
### Out of Scope (DO NOT TOUCH)
- Building the mobile UI.
- Modifying the Postgres schema.
- Implementing the API controllers.

## Current State Analysis
`powersync.yaml` contains placeholder rules that allow all access to `users` and `households`.

## Implementation Phases

### Phase 1: Identity & Membership Rules
- **Goal**: Secure the core user and household entities.
- **Steps**:
  1. [x] Update `users` rule to filter by `id = request.auth.sub`.
  2. [x] Update `households` rule to filter by membership: `id IN (SELECT household_id FROM household_members WHERE user_id = request.auth.sub)`.
  3. [x] Add `household_members` rule to filter by `user_id = request.auth.sub`.
- **Verification**: Review YAML syntax for correct indentation and subquery structure.

### Phase 2: Domain Data Rules
- **Goal**: Secure inventory and transaction data.
- **Steps**:
  1. [x] Add `inventory_items` rule to filter by `household_id IN (SELECT household_id FROM household_members WHERE user_id = request.auth.sub)`.
  2. [x] Add `transactions` rule to filter by `household_id IN (SELECT household_id FROM household_members WHERE user_id = request.auth.sub)`.
  3. [x] Add `products` rule to allow all reads (global catalog).
- **Verification**: Ensure all domain tables from `schema.sql` are covered.

### Phase 3: Configuration Deployment
- **Goal**: Apply the new rules to the sync service.
