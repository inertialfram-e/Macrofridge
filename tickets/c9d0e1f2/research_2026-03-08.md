# Research: Mobile Inventory CRUD UI

**Date**: 2026-03-08

## 1. Executive Summary
The goal is to implement the core user interface for managing household inventory within the Expo mobile application. This UI will allow users to view, add, edit, and delete inventory items, with data being persisted and synchronized via the PowerSync SDK.

## 2. Technical Context
- **Affected components**: `apps/mobile/src/components`, `apps/mobile/App.js`.
- **Current behavior**: The app has an authentication flow but no inventory-related UI.
- **Logic and data flow**: The UI will use the `PowerSyncDatabase` instance (from `src/lib/powersync.ts`) to execute SQL queries and mutations. PowerSync will handle the synchronization of these changes in the background.

## 3. Findings & Analysis
- **Navigation**: The app currently doesn't have a navigation library (like React Navigation or Expo Router). We should probably add one to support multiple screens (Auth, Inventory List, Add/Edit Item).
- **Inventory List**: Needs to display `custom_name` or linked product name, `quantity`, `unit`, and potentially `expiration_date` or `use_soon_flag`.
- **Add/Edit Form**: Needs inputs for all the fields defined in the `inventory_items` table in `schema.ts`.
- **Data Access**: We can use the `db.watch()` method from PowerSync to reactively update the UI when the local database changes.
- **Components Needed**:
  - `InventoryList.tsx`: Main view for displaying items.
  - `InventoryItem.tsx`: Individual row component.
  - `InventoryForm.tsx`: Screen/Modal for adding/editing.

## 4. Technical Constraints
- The UI must handle the asynchronous nature of database operations.
- We need to ensure that the `household_id` is correctly associated with new items. This requires knowing which household the current user belongs to (logic to be implemented in Phase 2).

## 5. Architecture Documentation
The inventory UI follows a reactive pattern. The UI observes the local SQLite database via PowerSync. When a user performs a CRUD operation, the UI executes a SQL mutation, and PowerSync automatically triggers a refresh of the observed queries, ensuring the UI is always in sync with the local state.
