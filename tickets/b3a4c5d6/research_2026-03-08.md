# Research: Mobile Household Management UI

**Date**: 2026-03-08

## 1. Executive Summary
The goal is to implement the user interface for managing household membership within the Expo mobile application. This UI will allow users to create a household, view current members, and potentially invite others or join an existing one. All data will be synchronized via the PowerSync SDK.

## 2. Technical Context
- **Affected components**: `apps/mobile/src/components`, `apps/mobile/App.js`.
- **Current behavior**: The app has an authentication flow and an inventory list, but no household management UI.
- **Logic and data flow**: The UI will use the `PowerSyncDatabase` instance to interact with the `households` and `household_members` tables. We need to ensure that every user is associated with at least one household to use the inventory features.

## 3. Findings & Analysis
- **Navigation**: We still don't have a formal navigation library. We'll continue with conditional rendering or tabs for now.
- **Household Selection**: If a user belongs to multiple households, they should be able to switch between them. For MVP, we'll assume one household.
- **Member Display**: Needs to join `household_members` with `users` to show names/emails. Since `users` are synced based on membership (per our sync rules), this should work locally.
- **Creation Flow**: 
  1. User enters household name.
  2. SQL executes to `INSERT INTO households` and `INSERT INTO household_members` (as admin).
- **Components Needed**:
  - `HouseholdManager.tsx`: Main view for household settings.
  - `HouseholdForm.tsx`: Modal for creating a new household.
  - `MemberList.tsx`: Display of current household members.

## 4. Technical Constraints
- Every `inventory_item` requires a `household_id`. The UI must ensure this ID is available before allowing item creation.
- Security: Only admins should be able to rename a household or remove members (logic partially implemented in sync rules).

## 5. Architecture Documentation
The household management UI follows the same reactive pattern as the inventory UI. It watches the `households` and `household_members` tables to provide real-time updates when membership changes or when a user joins a new household.
