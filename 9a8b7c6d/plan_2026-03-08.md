# Core Auth Implementation Plan

## Overview
Implement the core authentication layer using Supabase Auth. This includes setting up the Supabase client in the mobile app, creating a login/signup UI, and implementing authentication middleware/guards in the NestJS API.

## Scope Definition (CRITICAL)
### In Scope
- Install Supabase dependencies in `apps/mobile` and `apps/api`.
- Implement `apps/mobile/src/lib/supabase.ts` client.
- Create `apps/mobile/src/components/Auth.tsx` (Login/Signup).
- Implement `apps/api/src/auth/auth.guard.ts` to verify JWTs.
- Add an authenticated route to `apps/api/src/app.controller.ts`.
### Out of Scope (DO NOT TOUCH)
- Connecting PowerSync to Auth (Phase 2).
- Household management (Phase 2).
- Advanced profile management.

## Current State Analysis
Mobile and API apps are scaffolded but lack any auth logic. `App.js` and `app.module.ts` are the primary entry points.

## Implementation Phases

### Phase 1: Dependency Setup
- **Goal**: Install required libraries.
- **Steps**:
  1. [x] Run `pnpm add @supabase/supabase-js` in `apps/mobile`.
  2. [x] Run `pnpm add @supabase/supabase-js` in `apps/api`.
- **Verification**: `package.json` files show new dependencies.

### Phase 2: Mobile Auth Integration
- **Goal**: Implement login and signup UI/Logic.
- **Steps**:
  1. [x] Create `apps/mobile/src/lib/supabase.ts` with client initialization.
  2. [x] Create `apps/mobile/src/components/Auth.tsx` with basic email/password form.
  3. [x] Update `apps/mobile/App.js` to conditionally show Auth or Home based on session.
- **Verification**: Run `pnpm dev` in `apps/mobile` and see the login screen.

### Phase 3: API Auth Guard
- **Goal**: Protect API routes with JWT verification.
- **Steps**:
  1. [x] Create `apps/api/src/auth/auth.guard.ts`.
  2. [x] Use Supabase client to `getUser(token)` in the guard.
  3. [x] Apply the guard to a new `GET /profile` endpoint in `app.controller.ts`.
- **Verification**: `curl -X GET http://localhost:3000/profile` returns 401 without a valid token.
